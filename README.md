# Industrial Vision

Программный модуль технического зрения для промышленного мобильного роботизированного комплекса.

## Возможности

- Получение видеопотока с камеры или из видеофайла.
- Обнаружение и отслеживание людей.
- Контроль нахождения людей в запрещённых зонах.
- Контроль средств индивидуальной защиты: касок и жилетов.
- Обнаружение огня и дыма.
- Эвристическое обнаружение разливов.
- Регистрация событий и сохранение снимков.
- REST API для получения состояния системы и событий.
- Логирование и сбор метрик производительности.

## Технологии

- Python 3.13
- OpenCV
- NumPy
- Ultralytics YOLO
- FastAPI
- Uvicorn
- Pytest
- ONNX Runtime
- Docker

## Структура проекта

- `src/capture/` — получение видеопотока.
- `src/inference/` — обнаружение объектов и запуск обработки.
- `src/analytics/` — аналитика СИЗ и обнаружение разливов.
- `src/zones/` — геометрия и обработка зон интереса.
- `src/events/` — регистрация событий.
- `src/api/` — REST API.
- `src/monitoring/` — логирование и метрики.
- `configs/` — конфигурация системы.
- `tests/` — автоматические тесты.
- `models/` — файлы моделей, если они загружены в проект.
- `events/` — сохранённые события и снимки.

## 1. Подготовка окружения

Для запуска требуется Python 3.13 и установленные зависимости проекта.

Перейдите в корневую папку проекта и создайте виртуальное окружение:

```powershell
python -m venv .venv
```

Активируйте его:

```powershell
.\.venv\Scripts\Activate.ps1
```

Установите зависимости:

```powershell
python -m pip install -r requirements.txt
```

Убедитесь, что необходимые файлы моделей доступны по путям, указанным в `configs/configuration.yaml`.

## 2. Запуск обработки видео через терминал

Для запуска обработки с первой доступной камеры выполните:

```powershell
python -m src.inference.detect_camera --source 0
```

Для запуска с видеофайлом укажите путь к файлу:

```powershell
python -m src.inference.detect_camera --source "data\test_video.mp4"
```

Замените путь на фактическое расположение видеофайла.

Во время работы система обрабатывает кадры, выполняет обнаружение объектов и проверяет условия формирования событий.

## 3. Запуск REST API

В отдельном терминале активируйте виртуальное окружение и запустите сервер:

```powershell
python -m uvicorn src.api.server:app --reload
```

После запуска доступны следующие адреса:

- Swagger UI: `http://127.0.0.1:8000/docs`
- Проверка работоспособности: `http://127.0.0.1:8000/health`
- Состояние системы: `http://127.0.0.1:8000/status`
- Список событий: `http://127.0.0.1:8000/events`

API позволяет обращаться к реализованным HTTP-endpoint для получения состояния системы и информации о событиях.

Запуск API не следует считать автоматическим запуском обработки камеры: это отдельные процессы, если они специально не объединены в конфигурации запуска.

## 4. Запуск через Docker

Убедитесь, что Docker Desktop запущен.

```powershell
git clone https://github.com/alyesha27/industrial-vision.git
cd industrial-vision
docker compose up --build -d
```

Конкретный состав запускаемых сервисов определяется Docker Compose-конфигурацией проекта.

Для сохранения событий между перезапусками контейнера необходимо настроить монтирование каталога `events`. Доступ к веб-камере из контейнера также требует отдельной настройки; для проверки Docker-сборки можно использовать видеофайл.

## 5. Проверка автоматических тестов

Для запуска тестов выполните:

```powershell
python -m pytest -q
```

Тесты проверяют реализованные компоненты системы. Результат выполнения следует оценивать по фактическому выводу pytest.

## 7. Результаты работы

При возникновении события система сохраняет данные события и снимок кадра в каталоге `events`, в соответствии с логикой реализации.

Для демонстрации работы необходимо показать видеопоток, обнаруженные объекты, ROI, не менее двух различных событий, соответствующие файлы `event.json` и snapshot, а также работу API.

## 8. Конфигурация

Основные параметры находятся в `configs/configuration.yaml`.

В конфигурации задаются источник видео, пути к моделям, пороги уверенности, координаты зон, параметры подтверждения событий и каталог хранения результатов.

После изменения параметров перезапустите обработку, если система загружает конфигурацию только при старте.

## 9. Ограничения

Результаты обнаружения зависят от качества видеопотока, освещения, ракурса камеры, выбранных моделей и порогов уверенности.

Обнаружение разливов реализовано эвристически и не является полноценной нейросетевой сегментацией жидкости. Система предназначена для демонстрации и проверки реализованных сценариев; её результаты не следует считать гарантированным промышленным средством обеспечения безопасности.
